# 热度、完整度与准入规则

## 热度分

热度分用于排序，不是安全分或产品质量结论。当前由以下公开信号组合：

- Stars 对数得分，最高 30 分。
- 7 日增长，最高 32 分。
- 30 日增长，最高 14 分。
- 最近推送活跃度，最高 16 分。
- 新项目时效性，最高 8 分。
- Official MCP Registry 条目加 6 分。

历史不足时，7 日或 30 日增长保持为空，不伪造为真实增长。排序依次比较热度分、7 日增长、Stars 和仓库名。

## 元数据完整度分

`metadata_quality_score` 只检查公开资料是否足够完整：仓库格式、简介、主题、更新时间、Stars、Registry、语言、许可证、主页和未归档状态。它不检查恶意代码、依赖安全、数据外传、权限设计或实际可用性。

## 准入

- 动态条目需要满足最低元数据完整度阈值。
- 普通 GitHub 项目需要达到最低 Stars；Official MCP Registry 条目可以不受 Stars 门槛限制。
- 明确排除的聚合仓库、协议仓库或非 Server 项目不会进入目录。
- 初始扩容期和稳定期使用不同的每日准入上限。
- 月度复盘只会在目录超过目标规模时执行替换，并为新条目保留观察期。

详细、可复用的数据见 [JSON 数据集](../data/mcp-directory.json)。
